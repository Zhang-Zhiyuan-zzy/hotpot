## 1. 目标与应用范围

引入 `MetalCluster` 表示可作为整体使用的金属结构单元。内部是图或点云结构，外部
是具有多个键连位点的超原子；后续用于结构识别、组装、几何处理和计算输入投影。
范围包括单金属及多金属单元，金属数目不作为统一的最低限制。

| 应用例子 | 后续由注册定义确定的内容 |
|---|---|
| UO2、VO2、VO | 金属—氧单元边界、表示及对外连接位点 |
| 双金属桨轮，如 (Cu-Cu)OOCR、(Ru-Ru)OOCR | 双金属核、羧酸桥与外围连接的划分 |
| Zr6(u3-O)6(OH)6 | 多金属氧/羟基单元、桥联关系与外围位点 |
| Fe3O | 三金属含氧单元及其连接方式 |

这些简写是应用范围示例，不据此推定完整键型、价态、电荷、自旋、质子化或配体
归属，也不在当前建立任何具体匹配模板。首个结构定义及各类匹配通式由用户后续规定。

## 2. 对象模型与现有类型的关系

| 层面 | 框架建议 |
|---|---|
| 注册定义 | 每种受支持结构先注册；区分结构定义与某个分子中的具体实例，定义可追溯 |
| MetalCluster 实例 | 关联一个 Molecule 中的成员及注册定义，成员边界和连接位点按该定义解释 |
| 内部结构 | 通过成员引用或任务快照呈现图/点云；原子、键、坐标沿用各自唯一事实来源 |
| 外部结构 | 将整体投影为一个具有多个连接位点的超原子，位点映射回内部成员或连接区域 |
| Molecule 关联 | 规划 `Molecule.metal_clusters -> list[MetalCluster]`，具体发现与登记流程后定 |

超原子是结构层次中的使用角色。建议采用组合关系，与 Atom 保持独立类型；不为其
编造 atomic_number，不将它直接插入真实原子/键集合。内部图与外部收缩图按任务
生成，复用现有拓扑基础，不另建持久的分子拓扑权威。

注册限定于 MetalCluster 的领域定义，不扩展为通用规则注册或任意字段注入。
注册定义和实例关联的存储、来源与生命周期后续统一设计，避免增加相互复制的
模板、匹配、结果和句柄对象家族。显式关联与推断匹配应当区分；事实变更后的
有效性沿用共同协议，昂贵重匹配仅在需要时运行。

## 3. 当前登记与后续实施边界

Plan20 当前只登记一种新类型 `MetalCluster`、其层次关系及未来 Molecule 属性，
不选择具体 cluster 模板，也不实现空壳生产类、匹配算法、持久注册表或收缩图。
本阶段的“登记结构”指登记类型骨架；逐类结构注册等待用户给出定义。

用户已指定类型名和未来入口：

```text
MetalCluster
Molecule.metal_clusters -> list[MetalCluster]
```

建议该属性用于读取关联实例；返回 list 的容器语义、成员顺序、未知/失效状态和
是否按需匹配在实施前明确。构造器、导出路径、成员字段、注册/匹配/编辑方法及
其他公开属性保持留白，逐项审阅后设立，不由此草稿自动推出。

## 4. 后续工作包

1. 用户给出首个注册结构或匹配通式，确定内部边界、连接位点及允许的表示。
2. 设计最小注册与匹配机制，明确多重/重叠匹配、来源及生命周期；复用既有图与几何能力。
3. 实现 MetalCluster 与 Molecule 的关联入口，再逐步接入需要超原子的组装和计算流程。
4. 记录结构映射与接口契约验证、逐例科学观测和实施前后效率；扩大已审注册结构范围。

Plan21 在相关 Plan20 所有权、拓扑与公开接口协议稳定后分批实施，无需阻塞 Plan20。
独立簇的构造方式、注册格式、周期边界、嵌套/共享、几何与化学判据、序列化和后端
适配均待后续确定；本草稿不展开数据布局、算法、API 签名或测试清单。
