# Stage15 — Crystal spatial symmetry and molecular expansion

Owner-directed additional Plan20 branch, registered and substantively revised on
2026-11-04. The [detailed plan](review.md) starts with the complete proposed
Crystal property/method tree and abstract `SymmUnit` family, followed by one
exact affine algebra, molecular copying/cell expansion, complete possible
molecule relations and periodic geometry/topology observations.

`SymmUnit` instances are mathematical group elements with common `operate`,
composition, inverse, identity and powers. Supplied content is not assumed to be
a minimal asymmetric unit. Complete transformed overlap **and the same graph/
site bijection** support a possible relation; queries never authorize destructive
deduplication or decide scientific truth. Finite closed-loop linking is distinct
from geometric piercing; linked catenanes remain useful observations, and zero
linking number is not an unlink certificate. Crystal behavior uses Hotpot math/
topology, with only a separately justified table/CIF lookup candidate; no direct
or indirect OpenBabel/RDKit/CCDC Python API route is permitted.

This is a concrete design proposal, not runtime delivery or approval of its new
public signatures. The existing six-parameter cell remains the Stage0–12
contract until Stage15's connected, validated migration from `B_exp`. The plan
keeps the standard angle correction, oriented basis, single chemical owner,
periodic image maps and atomic lifecycle migration. Stage15A must resolve the
existing topology foundation's self/parallel periodic-edge limit explicitly.

Stage14D prepares against 15A's accepted schema, then consumes 15B/C's implemented
domain and affected 15E format closure. Stage15 publishes and closes its own
domain without waiting for the shared PyG fixture; Stage14 owns that integration.
All runtime, scientific, package and overall-task gates remain with the parent.
