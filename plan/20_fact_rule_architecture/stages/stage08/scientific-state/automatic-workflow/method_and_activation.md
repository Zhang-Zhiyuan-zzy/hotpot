## Scientific quantities and priority

The scientific state retains distinct net charge Q, formal charge, oxidation state, local spin and molecular 2S. Oxidation state is ionic electron-bookkeeping attribution, not an experimentally calibrated probability or a substitute for molecular charge. The existing hard validators, represented-H inventory, component partition, charge/OS conservation and spin-coupling arithmetic remain authoritative. Hard-invalid or mutually contradictory complete supplied evidence fails locally. Within admissible paths, explicit invocation state constrains selection before applicable specific rules and named common defaults.

Operations capture `MolecularFacts` once from an owned prepared copy. The private `_state_request_from_molecule(mol, facts, request)` reads actual declaration presence/value/source, supplied atom formal-charge presence/source and canonical radical occurrences; it does not read an inferred public charge/spin getter or mutate the caller. A numeric zero without supplied presence is not a source declaration. Present source zero is evidence. Existing explicit request fields win over stored declarations. Complete atom coverage may supply a source total charge; a complete component may supply component charge. Partial supplied charges remain partial. Coordination edits can invalidate aggregate coverage without deleting actual supplied per-atom values.

OPTIONAL-015 v1.0.0 publishes complete supplied component charges in SOURCE_EVIDENCE using existing ionic `CoordinationCountingCandidate` factors. Components include disconnected spectator ions; coordinated metal centers remain center-OS subjects. Source-aware OPTIONAL-002/003/004 v1.1.0 omit a source-counted component. L/X templates also omit components containing partial supplied atom charge evidence. The neutral-L rule requires an ordinary neutral whole-component valence pattern or an exact component signature, so a neutral donor no longer asserts that an entire remotely charged ligand is neutral.

OPTIONAL-016 v1.0.0 runs after existing coordination templates. An uncounted component receives the sum of supplied site charges plus zero at unspecified sites under `representation_default:unspecified-site-formal-charge-zero-v1`. This is modeled completion. It is not complete verified source charge. The rule then supplies COMPONENT spin under the component's parent charge identity. Supplied nonzero radical counts use the named local-highest-spin assumption; otherwise the named component default is the lowest electron-parity spin. The radical model does not enumerate alternative exchange states within a component. Unknown H or a missing site element cannot supply complete component spin.

## Periodic and spin defaults

The existing periodic registry preserves `.states` as its unranked possible domain and appends defaulted `common_states`, `important_states`, `default_state`, `default_basis`. RSC common/most-important metadata supplies a prior, not a probability or a universal chemical default. A unique important state supplies the named general default. For several important states, choose the least-absolute nonzero important state; when importance is absent, apply that convention to common states. Thus Sn/Pt2, Ir1 and Xe2 are explicitly modeled choices. A blank/unknown common row uses elemental0 as a model reference. It does not become an observed common state; Nh's possible domain remains empty. The five added possible states Ru0/Rh0/Pd0/Ir0/AuIV are directly source-attributed additions. All118 rows retain source/model missingness.

Existing scoped Ln/Am/Cm/Th providers retain their center domains and precede the general periodic default. Generic single-atom coordinated centers offer the named default plus existing possible-state alternatives; only the declared default receives its commonality rank. Registered ionic configurations own their local-spin domains. Only an unregistered ion path receives the named lowest-ion-parity spin. Neutral isolated atomic spin references are never used as molecular or ionic multiplicity lookup tables.

Each generated spin candidate is guarded by the selected charge/OS parent identity. Existing intercomponent/center coupling enumerates allowed total spins. After prior authority, assumption severity, specific commonality and f-Hund ranks, the final named decision preference is the lowest coupled molecular 2S. This preference is an execution convention, not a physical ground-state assertion. Scientific ambiguity, alternatives and the rationale remain visible. Explicit supplied molecular spin is retained as an existing MOLECULAR contribution while Q awaits derivation, then validated by common composition. Lewis enumeration waits for a hard-valid charge candidate rather than treating pending Q as a failed prerequisite.

The existing bounded resolver remains the only composer and selector. The unchanged limits are64 values/factor,4096 expanded paths,1024 frontier entries. Truncated/open domains and non-equivalent ties preserve certification or abstention. The final lowest-spin preference needs a conservative frontier upper bound of0 for `-2S`; arbitrary negative raw adjustments to that replaced coordinate cannot narrow this bound. ## Backend projection and connected consumers

Physical molecular 2S and ordinary-GFN active UHF are distinct. Pinned official xTB6.7.1 source initializes active contributions from Z−ncore and overrides Ce–Lu to3. Its wavefunction electron count is the sum of these contributions minus Q, with odd-electron UHF fallback1. For f-in-core centers there is no safe direct conversion from physical f spin to active UHF. Do not subtract physical f spins from molecular 2S. Existing execution selection prefers hard-valid explicit UHF, compatible exact-context execution history, a safe physical-spin projection, then the named lowest legal active parity default. GFN-FF remains charge-only. EuIII with a closed ligand may therefore retain physical2S6/M7 while ordinary GFN2 executes activeUHF0. Ordinary GFN energies do not establish reliable spin-state ordering.

The xTB context and stream validator share one pure active-electron helper; unsupported method/element combinations still fail explicitly. CBond's new predicted metal–donor bonds use canonical DATIVE/order1 with donor-to-metal direction; original input bonds and trained features are preserved. Composition changes clear inherited molecular declarations while retaining atom source facts. The registered Python/Open Babel route projects metal–nonmetal DATIVE to external SINGLE for that backend; canonical Hotpot facts remain authoritative through its controlled return. This is a declared lossy external bond-kind projection.

CLI and stage options with absent `--state-policy` pass `None` to the shared resolver: semantic metal coordination selects `COORDINATION_SCREENING_V1`, ordinary inputs select `STRICT`. Explicit policy flags retain their meaning. Source binding uses the existing net-charge finding `SOURCE.MOLECULE_STATE_BINDING` with `(raw_source_identity, profile_artifact_digest)` or `(raw_source_identity, "strict")`. Geometry alone preserves scientific identity and permits exact in-memory bundle reuse. Changed supplied charge/spin, formal-charge provenance, radical occurrences or screening artifact requires resolution. Structurally mismatched carried facts remain rejected. The pipeline payload digest reuses this source identity rather than duplicating raw-layout reads. Absent declaration/atom-charge slots normalize their unused backing value/source toNone in both raw and evidence digests, preserving semantic absence across current-factual codecs. The carried binding checks the screening artifact digest, not a separate aggregate of every periodic/prior data file. Accepted root lifecycle decision2026-11-05: any periodic/prior/default data change used by this profile MUST accompany a profile artifact/version revision. This invalidates carried bundles through the existing digest binding; the changed-profile rebind regression verifies that boundary. Runtime data remain fixed within an invocation/install. No hot-edit data mutation API or aggregate source hashing is added. A data-only manual edit without the required profile revision violates this maintenance contract.

The existing private current-factual CIF codec is reused for reserved Hotpot SDF transport with an exact structure SHA binding. It restores declaration absence/source, formal-charge presence/source, radical namespace and DATIVE kind/direction before xTB metadata validation. Facts-only FF/CBond records use the same path. Plain external SDF keeps ordinary imported semantics; metal SINGLE is never guessed to be DATIVE. Full frame/session history and arbitrary persisted scientific-bundle restart are outside this correction.

For bounded CLI state replay, restored source facts are resolved first. If their selected identity differs from recorded provenance, the recorded total charge may reconstruct a prior explicit CLI request only when the shared resolver reproduces the exact recorded scientific identity. No execution starts until that check passes. This permits both automatically derived charge and earlier explicit CLI charge without promoting every result Q into a user declaration. It may require two source resolutions; it still performs one public calculation. It does not recover arbitrary custom provider/request configurations.
